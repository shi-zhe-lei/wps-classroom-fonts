# 隐私与公开发布

这个公开版本由离线工具整理而来，首次建立 Git 历史前已完成以下清理：

- 未复制历史安装日志、检查报告、截图和个人使用记录。
- 重写了面向具体电脑的说明，移除了私人账号路径及固定盘符。
- 移除了 macOS 的 `.DS_Store`、`._*` 和相关附属文件。
- 未保留原下载压缩包；第三方许可证中的原始署名仍完整保留。
- 公开字体限于 9 个 STIX Two 文件，其余 49 个扩展字体仅用于本地准备并被 Git 忽略。

## 以后运行会记录什么

默认只记录操作、分组、字体名称、校验或错误结果。不读取课件内容，不获取账号名或主机名，不上传遥测，不在安装期间联网。

日志保存在 `${XDG_CACHE_HOME:-$HOME/.cache}/wps-classroom-fonts/logs/`，新日志权限为 `0600`。终端及日志中的账号主目录和项目目录替换为 `<home>` 与 `<package>`。

这不意味着所有手工附加信息都被自动匿名化。截图、系统工具的额外输出或自行编辑的文档仍需要提交者检查。

## 发布前检查

```bash
git add .
python3 tools/verify-public.py
git diff --cached --stat
```

检查器读取暂存区的实际 Git 对象，而不是只检查当前文件夹。它拒绝日志、临时压缩包、未批准字体、符号链接、非英文文件名、可识别的账号路径及常见凭据格式。也可以用 `--ref HEAD` 检查已有提交。

自动检查不能穷尽所有类型的个人信息。新文档、截图、作者身份和提交内容仍需人工审阅。当前仓库从整理后的公开文件建立历史，提交使用维护者明确指定的身份；作者姓名和邮箱会保留在 Git 历史中。项目级 Git 身份设置不会改变全局 Git 设置。

## 发布包的边界

`tools/build-release.py` 从通过检查的 `HEAD` 提交构建 ZIP。Git 忽略的文件不会进入发布包。把整个本地目录拖入压缩软件会绕过这个边界。

如果误提交了敏感内容，仅添加 `.gitignore` 不能清除已有历史，应在发布前清理相应提交；若涉及凭据，还应撤销和更换凭据。
